# ensem_room207

Gazebo environment of ENSEM Room 207: the QCar large track on its 20 cm platform with traffic lights and the UrbanLoop banner, and the room around it (brick walls with windows, blinds and radiators, U-shaped entrance with a double door, whiteboards with drawings, workstations with screen images, chairs, teacher desk, drawer cabinet, LIMO boxes).

The track is centred on the origin, as in `qcar_large_track`, so robot spawn poses and odometry plots are the same in both worlds.

Developed and tested with Ubuntu 20.04, ROS 2 Foxy and Gazebo Classic 11.

## Usage

Room only:

```bash
ros2 launch ensem_room207 ensem_room207.launch.py
```

With the LIMO, RViz and the control window (`room207_limo` package, Room 207 is its default world):

```bash
ros2 launch room207_limo demo_simu.launch.py
```

The track is 20 cm above the floor: spawn robots at z = 0.35 m (default `spawn_z` of `room207_limo.launch.py`).

## Hidden light markers

Gazebo draws a marker for each light source in the GUI. The world loads the GUI plugin `libensem_room207_hide_light_markers.so` (`src/hide_light_markers.cc`), which hides these markers; the lights themselves are unchanged.

- The plugin is built only when Gazebo is found, so the package also builds on a robot without Gazebo.
- Its folder is added to `GAZEBO_PLUGIN_PATH` by the package environment hook and by the launch files. If gzclient prints `Failed to load plugin libensem_room207_hide_light_markers.so`, source `install/setup.bash` again in a new terminal.

## Room dimensions

The room is generated by `scripts/generate_room.py`. **The dimensions are estimates from a hand-drawn plan and photographs, scaled with the track size.** After measuring the room, update the values at the top of the script and regenerate:

```bash
python3 scripts/generate_room.py
colcon build --packages-select ensem_room207
```

Do not edit `models/room207_room/model.sdf`, `models/room207_room/materials/scripts/room207_room.material` or `worlds/ensem_room207.world` by hand: they are overwritten by the script.

The textures are made by `scripts/generate_textures.py` (needs `python3-pil` and the Liberation/DejaVu fonts): bricks (outside of the walls with windows), floor tiles (40 cm, off-white), the two whiteboards (kinematic bicycle model, lateral dynamics state-space model) and the workstation screens (Simulink, ROS 2 terminal, Gazebo). The Gazebo screen shows a render of the room passed with `--gazebo-view render.jpg`. The PNG files are committed, so run the script only to change them.

Frame convention (the track keeps the `qcar_large_track` frame, the room is placed around it):

- the track spans 4.88 m along x and 6.20 m along y, centred on the origin;
- on the room plan (track at the top, classroom at the bottom):
  plan up = world -x, plan down = world +x, plan left = world -y (whiteboards, door), plan right = world +y (windows).

The Gazebo GUI opens with a view oriented like the room plan.

The workstation screen images are part of the `room207_room` model: the generator places them in front of the screen of each workstation listed in `furniture()`. Move a workstation in the script, not in the Gazebo GUI, so that its screen image follows.

## Lighting

The world uses only a soft daylight (no specular) and ambient light: the ceiling lamps are not modelled, so that the only reflections come from the windows. Reflection-only lights at the windows around the track (no diffuse light, only specular) create the reflections of the windows on the track mat and, more softly, on the floor tiles. The track material (`models/room207_track/materials/scripts/room207_track.material`) keeps the exact colours of `SDCS_MapLayout.png` and only adds the specular highlights of these lights, to reproduce the glare of the windows seen by the cameras on the real mat. Tune the `specular` line of that material to make the glare stronger or weaker (`0 0 0 1 40` removes it).

Gazebo Classic has no real-time mirror reflections: glass and floor do not reflect the room.
